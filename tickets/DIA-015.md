# DIA-015 — Scoring correctness: the sacrifice/batter-outcome rework, plus five entry bugs
**Spec:** §13, §13.6, §4.3, §15.1, §15.3
**Sequencing note:** M1, and the first half **gates DIA-009** — the box score that ticket renders is
the first consumer of `BatterOutcome`, and it is currently keyed per *batter* rather than per plate
appearance. Everything else here is independent and can ride along whenever.
**Goal:** make the scoring engine right about sacrifices and plate appearances, fix five entry bugs
found by playing the app, and remove one half-written field.

## Part 1 — the sacrifice / batter-outcome rework (gates DIA-009)

Found by reading `_sacrificeFor` and `_batterOutcome` against the rulebook. Every one of these is
the same failure: **the common case written down as the rule.** They belong together because they
are all one function's worth of branching, and because fixing them separately would mean four passes
over the same code.

**The dropped-fly sacrifice fly is unenterable.** The rule credits a sac fly on either of two
clauses — the ball is *caught* and a runner scores, **or** it is *dropped* and a runner scores if in
the scorer's judgment they could have scored had it been caught. Only clause (1) is implemented, and
three separate guards block clause (2), all false on a muffed fly: `landingIsCaught`, `wasOut` (she
reached on the error, so she is not retired — yet it is still a sacrifice and still not an at-bat),
and `anyChargedError` (the error is the entire premise).

`anyChargedError` is wrong even for clause (1): a runner tags and scores, the throw home gets away,
another runner takes a base — still a sac fly plus an error. **Delete it.**

**It demands the runner start on third.** The scoring-runner test requires `from == 3`, and the
variable is named `scoredFromThird`. The rule says only that *a runner scores after the catch*. A
runner on second tagging up on a deep fly is legal and happens. Condition should be `to == 4` alone;
rename the variable, which encodes the wrong assumption in the vocabulary.

**Nothing asks.** `PlayDraft.invitesSacrifice` returns false unless the trajectory is a bunt, and a
test pins that a fly ball never asks. So even with the derivation fixed, clause (2) has no way in.
Widen it: an airborne ball **not** caught, a runner scores, fewer than two out at contact. Clause (1)
must keep deriving silently — do not start asking there.

**The judgment is honored in one place out of four.** `_batterOutcome` consults `sacrifice` only in
its `reach == null` branch. The other three return paths ignore it, and `BatterOutcome.atBat`
defaults to `true` — so **any sacrifice where the batter reaches base loses the credit and is charged
an at-bat.** That is exactly clause (2), and a sac bunt where she reaches on an error or a fielder's
choice, which is still a sacrifice bunt by rule. Resolve `sacrifice` once, above the branching, and
apply it to whichever result is built — the way `rbi` already is. Compute `atBat` explicitly on every
path; the default is what hid this.

**`_batterOutcome` is keyed per batter, not per plate appearance.** `own` collects every advance that
runner ever made, and `reach` is `firstOrNull` — so a batter's result is **pinned to her first plate
appearance of the game forever**, and later baserunning can raise an earlier PA's hit rank. The RBI
loop scopes correctly with `batterAtTime`; the reach lookup has no such guard, and that inconsistency
inside one function is the tell. Latent only because M1 scores one half-inning.

The fix is structural: **the unit of official scoring is a plate appearance, not a batter.** Iterate
PAs, scope advances and outs to the PA the way `batterAtTime` already does, and let `atBat` /
`plateAppearance` become honest flags on a completed PA.

**Retire the `'batting'` sentinel.** It is written in one place and read nowhere, so the first thing
to sum `batterOutcomes` will treat a batter still standing at the plate as a completed row. And
`atBat: false` currently conflates *"a completed PA that is not an at-bat"* (walk, HBP, sacrifice)
with *"a PA that has not finished."* AB would be right and OBP wrong, which is the nastier failure
because it looks plausible.

**Decide first:** `BatterOutcome.scoring` is one string, so a clause-(2) sac fly can say
`sacrifice_fly` or `reached_on_error` but not both, though both are true and the error is charged
separately. `hit` and `atBat` are already independent flags there; the honest shape is probably a
`sacrifice` flag alongside them, with `scoring` holding what she actually did.

**Guiding rule (Mark):** every play goes through the same worker. Compute shared facts once, above
the branching; prefer skipping inside one loop over separate paths per case; make result fields
**required rather than defaulted**, because a default is a silent wrong answer for the case nobody
thought about and a required field is a compile error.

## Part 2 — five entry bugs

**The OUT menu offers "Tag" for the batter on a caught ball.** `_possibleHows` lists tag
unconditionally while everything around it is gated. She is out *by the catch*; there is no tag to
apply. Gate it `if (!caught || !isBatter)`. Note while in there: the list's **order is load-bearing**
— `_inferredHow` takes `.first` as the preselected chip — which is invisible from reading the list.

**The force chain ignores outs already recorded on this play.** `_forceChainLive` reads pre-pitch
occupancy plus `caught`, and nothing else. But a force is also removed when the runner behind is
retired: grounder to the first baseman, she steps on the bag, then throws to second — that runner
must be **tagged**, and we still offer "Force" *preselected*. Feed the draft's recorded outs in: a
base counts as occupied only if that runner has not already been retired, and the batter's anchor
pushes only while she is still live. Also kill the dead `_` arm in its switch, which silently reads
third base for an out-of-range value.

**Arrival quality is offered on batted balls.** `_receivingTypes` gates the clean/short-hop/high/wide
chips on the *touch type*, but `dropped` and `missed_catch` describe muffing a **throw** and muffing a
ball **off the bat**. Dropping a routine fly ball currently asks how the throw arrived, for a ball
nobody threw. Gate on **provenance** instead — did the preceding touch secure the ball — which
`PlayDraft.securedTouch` already computes.

**A wild throw retypes the wrong node.** Marking a throw wild means retyping the *thrower's* touch,
but the throw *arrives* badly and the receiver's node is the one that just appeared, so that is where
the finger goes. Confirmed in the field: a catcher's throw to first recorded `wild_throw` on
position 3, which would charge **E3 instead of E2**. The grammar itself is consistent — `wild_throw`
on a node means "this fielder threw it away," and a receiver who later throws it away is correctly
retyped on her own node — so do not "fix" that. Candidates: offer **"The throw was wild"** on the
receiving node, which retypes the previous touch; or withhold `wild_throw` from a receiver's chips
until she has thrown.

**The loose-ball popup offers ground-ball verbs between pitches.** With no trajectory, `airborne` is
false, so a catcher chasing a wild pitch is offered Fielded / **Booted** / **Deflected** / Missed it.
A catcher cannot boot a pitch, and nothing caromed off anyone. Narrow the choices when
`!battedBall`. Check whether `bobbled` is the honest word for the muffed pickup, which is chargeable.

**Label:** "Tag missed" → **"Missed tag"** in the chain strip's chip menu. Display only; the wire
value `tag_missed` is unchanged.

**The pickoff is enterable and completely untested.** `field_entry_surface.dart:941` offers
`('picked_off', 'Picked off', How.PICKED_OFF)` on §15.6's idle field — drag the runner, pick the chip,
commit — and **nothing in `test/` exercises it**. It is untested rather than unbuilt, which is the
worse of the two states to be in without knowing. Add coverage for the throw-over that retires the
runner: the `RunnerOut` carries `picked_off`, the putout and assist land on the right positions, and
the runner leaves the base.

Scoped by Mark, 2026-08-27: **a pickoff attempt with no consequence is not recorded.** *"I don't think
anyone cares about recording failed pickoff attempts."* That settles the open question from
`PickoffAttempt`'s deferral — the event is **not needed**, because the only case that wanted a new
anchor was the consequence-free attempt. DIA-008d solved anchoring generally: a between-pitch entry
hangs off the pitch that already exists, and a pickoff is one. The deferred
`ballInPlayEventId` → `anchorEventId` rename stays deferred; the name is genuinely wrong now (the
field holds either a BallInPlay id or a pitch id) but it is a schema change for naming alone, and
§21.5 makes that an atomic commit across two codegen targets and every fixture. Batch it with the
next real schema change.

**Fixture 06 is anchored to a string that resolves to nothing.**
`play_06_rundown_dropped_exchange.json` hangs all four touches off `"ballInPlayEventId": "pickoff"`,
and its note still asks for the `PickoffAttempt` event that is no longer coming. It passes only
because the engine treats the anchor as an opaque grouping key — so a **§14 acceptance play is
validating a shape the app can no longer produce**, which reads as coverage and is not. Re-anchor it
to a `PitchThrown` so it matches what the idle field writes, and delete the schema request from its
note.

One wrinkle worth knowing before starting: `fixtures_test.dart` seeds `GameState` from `setup` and
*then* folds the events, so introducing a pitch advances the count past the seeded one. Drop the
setup to `0-0` and let a `called_strike` bring it to the 0-1 the play intends. Nothing in `expect`
asserts the count, so this will not fail either way — which is exactly why it is worth doing
deliberately rather than leaving a fixture whose stream and setup disagree.

## Part 3 — drop `BallInPlay.retrieved` (schema change)

The field is populated only by the **two-tap ball path**; the fielder-drag path never sets it — which
is the path you would use for the case it exists for, a ball that gets past someone and is retrieved
elsewhere. So it is half-written, and a consumer cannot tell "possession was regained where it
landed" from "nobody recorded it."

Nothing is lost by removing it: **the retrieval touch already carries its own `location`** (§4.2),
always, on both paths, and more precisely — it says *who* regained possession as well as where. Two
sources for one fact, one of them unreliable, is worse than one.

Drop it from `schema/events/ball_in_play.schema.json`, from `PlayDraft`, and from the painter's roll
segment, which should read the first securing touch's location instead. §21.5's one atomic commit:
schema → regenerate Dart and TS → fixtures and tests. Check `fixtures/plays/` for uses before
removing, and note that removing a field is safe for recorded streams in a way removing an **enum
value** is not — an absent field just reads as null.

## Part 4 — the scorer makes the WP/PB call, always (§13.2 v0.49)

**Spec change already landed** (v0.49, three-place protocol done). This part is the deletion that
follows it. No schema change: `wild_pitch` and `passed_ball` are already `RunnerAdvanceReason` values
and the entry paths already write them (`play_draft.dart:278-279` maps the SafeResolution chips
straight onto them). The scorer's click has been recorded correctly all along — the projection just
refused to read it.

**What to delete.** `_pitchGetaways` in `official_scoring.dart` picks `PitchGetawayKind.passedBall`
vs `.wildPitch` by looking for a `missed_catch` touch on the pitch, never at
`advance.payload.reason`. Its own doc comment states the policy outright — *"comes from physics,
never from the advance's label"* — and spells out the consequence: *"a `passed_ball`-labeled advance
with no such touch is therefore scored a wild pitch."* Read the reason instead, and delete the
inference.

**Two things fall out with it:**

- **`_getawayReasons` should stop including `DROPPED_THIRD_STRIKE`** (line ~542). A D3K reach is an
  *entitlement to run*, not a statement about who let the ball get away — which is the distinction
  DIA-008c already established. Under v0.49 it is neither a wild pitch nor a passed ball unless the
  scorer separately says so, and the D3K resolutions already write `wild_pitch` / `passed_ball` when
  she does.
- **The entitlement-vs-cause special case goes with it** (line ~590, the `DROPPED_THIRD_STRIKE &&
  linked != null && !pitchReceivingTouchTypes.contains(...)` skip). It exists only to stop the
  inference reaching a wrong answer on D3K reaches. With no inference there is nothing to guard, and
  a branch that exists to correct another branch is exactly the edge-case shape this ticket's guiding
  rule rejects. **Net deletion, not a rewrite.**

**The strongest argument for the change is that the code already half-made it.**
`earned_runs.dart:97` decides earned-vs-unearned by reading `advance.reason == PASSED_BALL` — the
label — while `official_scoring.dart` overrules that same label with touch physics. So the two
subsystems already apply **opposite policies to one question**, and today a single advance can be
scored *unearned* because the scorer said passed ball while simultaneously being charged to the
**pitcher** as a wild pitch because no touch was recorded. That is not a disagreement about a rule;
it is one event producing two contradictory scoring facts. v0.49 picks the side that was already
implemented in half the codebase.

**Check while in there:** whether anything else reconciles label against physics. The spec now says a
disagreement between the two is *not* an error condition, so any code treating it as one — a
normalizer, a validator, a fixture assertion — is now wrong rather than merely redundant.

**Fixtures:** play-05 and play-11 both involve uncaught pitches; confirm their expected output is
unchanged, since the entry paths mint both the label and the touch and the two have agreed in
practice. If a fixture *does* move, that is the bug this part exists to fix showing itself.

## Accept

- A dropped fly with a runner scoring is enterable as a sacrifice fly, charges the error, and is a
  plate appearance but **not** an at-bat.
- A runner scoring from second on a caught fly credits a sacrifice fly.
- A sac bunt where the batter reaches on an error is still a sacrifice.
- A batter with two plate appearances in one game has two independent outcomes; the second is not the
  first.
- No caught fly offers a tag on the batter; no force is offered after the runner behind is retired;
  no batted ball asks how the throw arrived.
- New fixtures for the clause-(2) sac fly and the scoring-from-second sac fly.
- A `passed_ball` advance with **no** catcher touch recorded is charged as a passed ball, not a wild
  pitch — the case that is wrong today — and the reverse holds too: a `wild_pitch` advance is not
  turned into a passed ball by a touch that happens to exist.
- `official_scoring` and `earned_runs` agree about which advances are passed balls, because both read
  the same field.
- A pickoff that retires the runner has a test; fixture 06 anchors to a real event rather than to the
  string `"pickoff"`.
