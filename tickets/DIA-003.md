# DIA-003 — GameState projection engine
**Spec:** §4.4, §5, §7, §12.5
**Goal:** pure fold: List<GameEvent> → GameState {count, outs, inning half, bases, score, batter due, pitch counts}. Handle: outcome-driven count logic (foul at 2 strikes, foul_bunt K, D3K arming),
`unknown` outcome → uncertain-count flag, CountCorrection override + back-inference (mark inferred), VoidEvent/correction chains, InningHalfStart snapshot checkpointing (write + fast-path read), InningHalfEnd (§4.4): 'three_outs' auto-implied by the fold; other reasons (run_cap, time_limit, …) authoritative even with <3 outs.
**Design constraints:** batter-due is derived from the event stream on every fold — never cached positionally — so BattingOrderAdjusted (M2) slots in without refactor.
**Accept:** property test: fold(events) == fold(snapshot + tail). Unit tests for every count edge in §4.1. Uncertainty flag set/cleared per §12.5. run_cap close mid-inning flips the half correctly.
**Out of scope:** official scoring derivation (DIA-004), stats, BattingOrderAdjusted handling (M2).
